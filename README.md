# Задание 5. JWT Access/Refresh и управление сессиями

Изучить теорию

Внимательно ознакомиться с документом

Расширить модель данных

Добавить сущность UserSession (таблица user_sessions)

Создать enum SessionStatus

Реализовать UserSessionRepository

Доработать работу с JWT

Расширить JwtTokenProvider, разделив логику для двух типов токенов: access и refresh

Внести в payload токенов дополнительные claims

Обеспечить корректную валидацию обоих токенов

Реализовать сервис работы с парами токенов

Доработать контроллер аутентификации

Обновить обработчик POST /auth/login так, чтобы он работал с парой токенов

Добавить endpoint POST /auth/refresh

Проверка и тестирование. Воспроизвести следующий сценарий:

Шаг 1. Вызвать POST /auth/login, получить access и refresh.

Шаг 2. С access-токеном обратиться к защищённому эндпоинту, убедиться, что доступ есть.

Шаг 3. Вызвать POST /auth/refresh с текущим refresh-токеном и получить новую пару токенов.

Шаг 4. Повторно вызвать /auth/refresh со старым refresh-токеном и убедиться, что сервер возвращает ошибку (статус 401/403) и не выдаёт новую пару.

Шаг 5. Проверить, что статусы сессиям в БД проставляются корректно.
